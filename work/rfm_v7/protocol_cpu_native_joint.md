# 降步率与 CPU 原生预收缩的隔离复测

候选是 RFM37、Legendre37 和 FD176。前两者分别在步率 112 下使用原 CPU Recurrence、新 CPU 原生预收缩和原 CUDA Graph，再各加入步率 128 的 CUDA Graph 控制。FD176 保留步率 128，使用 CPU 缓冲带状解和 CUDA 原生稠密应用两条路径。五个区组内随机排列十条路径，共 50 次。RFM 按原登记顺序逐组使用五个种子，同块四条 RFM 路径使用同一个种子。确定性方法逐组重复。

启动前封存原步率筛查、新算子六条准确度记录、两个参考轨迹、原参考轴审计、各配对控制轨迹及全部运行依赖的 SHA-256。新算子附加 C 源和实际 DLL 哈希、编译器与标志、PE 架构。接受每次运行需要三网格七时刻的四项误差对两个参考均不超过 0.5%，保持交替涡脱落，并通过同离散 CPU 基准的字段与探针误差门槛。原步率筛查的经验收敛与防抵消判据作为选档来源保留。正式计时不重新选档。

CPU 固定亲和核及 BLAS 单线程。总耗时从创建求解器至最后同步和返回输出，包含计划、传输及清理，排除评分和保存。各区组内报告 CPU 新旧收缩之比、同种子同空间配置的 CUDA 步率 128 与 112 耗时比、两种 Galerkin 与同硬件 FD 的耗时比，以及同离散 CPU/GPU 耗时比。CPU 新旧收缩在固定步率下对照，CUDA 只改步率并保持其他参数固定。既有报告的时间分列保留。

步率 112 把 t=72 计算从 9,216 步降到 8,064 步。非线性评价减少 1,152 次，推进阶段 batched FFT 调用从 18,430 降到 16,126，每次非线性评价仍包含一逆一正两个 batch。原生预收缩主要改变每步的径向投影与隐式应用，FFT 数由步率改变决定。资格试跑可以并行，其时间不进入正式比较。
