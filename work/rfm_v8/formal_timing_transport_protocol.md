# Registered timing transport

`formal_timing_coordinator.py` accepts a frozen job document and a new output directory. It uses `solver_worker_formal.py` for each registered method, including finite differences. It launches a fresh child for every attempted slot. Transport-only verification uses the same worker admission and clock code with an injected synthetic solver.

## Protocol and scope

- Register `schema=rfm-v8-active-timing-1`, `status=frozen`, `mode=formal`, a cohort token, `coordinator_cpu`, `monitor_cpu`, `poll_interval_ns`, `max_poll_gap_ns`, `maximum_active_ns`, `budget_interval_ns=10000000000`, `max_budget_lateness_ns=2000000000`, three bounded worker timeouts, `known_background`, `source_hashes`, and ordered `requests`. Distinct logical processors are required. Prefer processors on separate physical cores. Limit the background allowlist to the previously authorized exact `(PID, birth FILETIME)` identity. Keep the independent monitor and coordinator roles bound to their actual process handles.
- Give each request the exact ordered `index`, `block`, `name`, `seed`, `arm`, `family`, `imports`, `config`, and `solve_args`. Include `schema=rfm-v8-worker-1`, the cohort `run_token`, the exact inherited `affinity_mask`, and `trajectory=trajectory_NNN.npz`. Freeze the full transitive source and numerical data dependency inventory, including the actual `rfm_v6/fd_full_band.dll` bytes for an FD arm. Bind the raw protocol bytes and recheck them and the source hashes after the queue.
- Preserve two 10-second preflight quiet guards and the 5% GPU endpoint limit. Use the existing 0.2, 0.5 and 1.0 CPU-second thresholds on registered 10-second active budgets and the last partial budget. The coordinator and monitor start before preflight as transport infrastructure. OPEN is acknowledged before the first timed worker launch and any solver preparation. It follows a completed boundary sample. Keep polling through the last attempted worker terminal record, per-slot transcript closure, and raw coordinator digest closure. Mark CLOSE before offline scoring and record the first post-close observation. Preserve preflight rejection, missing samples, external activity, and raw stopped attempts. An elapsed deadline leaves subsequent registered slots explicitly unattempted.
- The monitor runs on its own pinned process and replies immediately to registration commands. The coordinator obtains the child identity from the actual `Popen` handle, persists it and the monitor acknowledgement, then sends GO. The child authenticates a single byte-read request and checks the exact parent and own identities against that ledger. The solver clock includes setup, march, teardown and model release. The fresh-process clock starts immediately before `Popen` and ends at the flushed RETURN marker. Require solver time to fit inside GO-to-RETURN. Serialization happens after SAVE and terminal collection checks exact PID and birth, exit FILETIME, CPU counts and serial slot order.
- Save each attempted row and original machine transcript. Preserve available hashes if the coordinator or monitor fails. A completed clean sampled transport is still awaiting independent numerical qualification. Transport fixtures never support performance claims. A formal result also needs the separately frozen physical and implementation gates, complete probes, paired schedule and independent archive verification.

## Polling tradeoff

The transport smoke compares 1-second and 100-ms native census polling over a short synthetic worker lifetime. The certificate reports actual wall spans, largest gaps and process CPU time. Sampling at 100 ms consumed appreciably more of the monitor core. The proposed production choice is 1-second polling with a 2.5-second hard start-to-start gap and the unchanged 10-second budget and 2-second anchor-lateness gates. The lower cadence reduces monitor overhead and increases the time in which a short-lived process can escape observation. Use `no_sampled_external_activity` only within the scoped Python observations and aggregate GPU preflight endpoints. The lifecycle smoke contains a deliberately missed above-threshold process between polls, and the current account cannot open ETW. An audit can support the sampled scope while remaining explicit about those limits.
