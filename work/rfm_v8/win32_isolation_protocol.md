## Proposed registration

1. Freeze the protocol, solver and monitor hashes, exact schedule and seed order, Windows build, host and GPU configuration, maximum duration, sample cadence, and timeout behavior before the cohort. Use one cohort attempt per registered scale. Record every attempted slot and original timing marker. The candidate polling design targets 100 ms and rejects a start-to-start gap greater than 250 ms. Run a transport-only rehearsal at the chosen cadence and compare monitoring overhead before deciding whether to freeze these settings.
2. Calibrate the native process census against exact `GetProcessTimes` records from an owned live process. The x64 census obtains image, PID, parent, creation time and cumulative kernel/user counters in one system query. The public SDK exposes the prefix and reserves the bytes containing the time fields. The implementation checks their layout and brackets the parsed counts with the documented handle API. A build or ABI mismatch invalidates coverage. [Microsoft native process census](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntquerysysteminformation), [Microsoft GetProcessTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes)
3. Acquire query-only handles for the exact identities observed within the Python image scope. Preserve terminal counts and exit FILETIME from retained handles. An unavailable handle leaves the original census observation intact. A vanished identity without exact exit counts fails coverage and retains the last observed CPU lower bound. Use exact `(PID, birth FILETIME)` joins, parent consistency, monotonic counters, and the registered READY and RETURN identities for each owned child. Allow the frozen background identity and the actual monitor identity only by exact identity.
4. Run two prospective 10-second quiet preflight guards. Both preserve raw samples and require the known background and monitor identities throughout, with no other observed Python identity and aggregate GPU utilization at most 5% at each guard endpoint. Preserve the v7 CPU budgets. An external Python process above 0.2 CPU seconds, a known background process above 0.5 CPU seconds, or total known background above 1.0 CPU seconds within a registered budget interval trips the activity threshold. During the active interval, retain faster lifecycle snapshots between the original 10-second budget anchors. Preserve the 2-second maximum budget-anchor lateness. The final partial budget interval uses the same thresholds.
5. Persist the `OPEN` marker and its latest completed boundary sample before launching the first process, including a coordinator that prepares any scoring or solve state. Record each owned worker identity from its actual process handle before granting GO. Continue through the last owned worker's terminal record and the coordinator's closing journal and actual exit. Record `CLOSE` and the first post-close boundary sample. Bound the maximum active duration in the protocol. Archive preflight, active and post-close samples separately. An overdue worker, missing boundary, uncovered gap, unknown missing terminal, malformed ledger or failed numerical gate retains a diagnostic cohort. The active gate includes the preparation, fresh-process clock, solver clock, and inter-slot activity through close.
6. Make the verdict independently replayable from the archived raw samples, exact event and identity ledgers, timings, and numerical records. Preserve both external-activity and coverage findings when they occur together. `no_sampled_external_activity` applies to the monitored Python process scope and the registered endpoints. Keep process paths, command lines, and SIDs outside publishable evidence.

## What the smoke establishes

An actual registered child and an actual unregistered child produced exact matching terminal CPU counters through both sampler and owned handles. The unregistered child crossed the existing activity threshold. The injected post-census attach failure preserves the already captured identity and is accepted only when the exact owned terminal record fills the gap. Synthetic PID reuse and missing-boundary/over-limit gaps reject exemption and coverage. A deliberately sparse test missed an entire above-threshold process lifetime, so the prototype always reports `full_lifecycle_verified=false`.

The current account's attempt to open an empty, uniquely named ETW session returned access denied. The installed kernel process provider exposes process start/stop identity and exit time, with CPU cycles on newer stop versions. Cycle counts do not substitute for the 100-ns kernel/user thresholds. A future event-backed gate needs valid event ownership, checked loss counters, and exact terminal CPU evidence. Present results support only sampled coverage. [Microsoft ETW controller permissions](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-starttracea), [Microsoft ETW loss accounting](https://learn.microsoft.com/en-us/windows/desktop/ETW/event-trace-properties)
